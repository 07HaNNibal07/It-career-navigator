## Итоговая цель

## Этап 1 — Перейти к целевой модели данных

- Сразу перейти с локального SQLite на PostgreSQL и добавить Alembic-миграции; текущую тестовую SQLite-базу считать одноразовой.
- Привести `Person` к сущности `User` и создать связи: `User`, `Direction`, `Skill`, `SkillAlias`, `UserSkill`, `Vacancy`, `VacancyRequirement`, `Analysis`, `SkillStatistic`, `Roadmap`, `RoadmapItem`.
- Расширить профиль: целевое направление, целевой уровень и уровень владения каждым навыком.
- Добавить уникальные ограничения: email пользователя, каноническое имя навыка, псевдоним навыка, связь пользователя с навыком, внешний ID вакансии в рамках источника.

**Готово, когда:** чистая PostgreSQL-база поднимается миграциями и может хранить профиль, вакансии, требования, результаты анализа и roadmap.

- Реализовать защищённую внутренним API-ключом загрузку файла и сервис импорта: Pydantic-валидация, дедупликация по `source + external_id`, сохранение исходного текста и отчёт об ошибочных строках.
- Создать каталог навыков и `SkillAlias`: например, `Postgres` и `PostgreSQL` приводятся к одному `Skill`.
- Подготовить репозиторный демонстрационный набор вакансий для Python Backend Developer разных уровней.

**Готово, когда:** один импорт загружает валидные вакансии, не создаёт дубликаты и сохраняет отчёт по отклонённым строкам.

## Этап 3 — Интеллектуальное извлечение требований

- Добавить OpenAI-совместимый адаптер с настройками `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` в окружении.
- Определить Pydantic-схему структурированного ответа LLM: технологии, обязательность требования, опыт, уровень, языковые и дополнительные компетенции.
- Реализовать обработку одной вакансии: очистка текста → LLM structured output → Pydantic-валидация → нормализация навыков → сохранение `VacancyRequirement`.
- Добавить fallback на словарь и поиск ключевых слов, если LLM недоступна, вернула невалидный ответ или превысила лимит.
- Подготовить небольшой эталонный набор вакансий с размеченными требованиями для ручной оценки качества извлечения.

**Готово, когда:** каждая тестовая вакансия получает структурированные требования через LLM либо fallback, а невалидный ответ не ломает анализ.

## Этап 4 — Статистика, skill gap и roadmap

- Создать запуск `Analysis` для выбранных направления, уровня и набора вакансий; хранить статус, время запуска и результаты.
- Рассчитывать востребованность навыка как долю вакансий, где он встречается; учитывать обязательные требования с повышенным весом.
- Определять skill gap как требуемые рынком навыки, отсутствующие в `UserSkill`.
- Ранжировать roadmap по приоритету: востребованность × вес требования; показывать навыки от наиболее важных к менее важным.
- Сохранять `SkillStatistic`, `Roadmap` и `RoadmapItem`, чтобы пользователь видел историю запусков и мог отмечать изученные пункты.

**Готово, когда:** для демонстрационного набора пользователь с навыками Python/FastAPI/PostgreSQL получает ожидаемые пробелы вроде Docker, Redis и CI/CD с объяснимым порядком.

## Этап 6 — Фоновые задачи и контейнеризация

- Добавить Celery worker: импорт, LLM-извлечение и расчёт анализа выполняются вне HTTP-запроса.
- Использовать RabbitMQ как broker, Redis для состояния задач/кэша, PostgreSQL как основное хранилище.
- В `docker-compose.yml` определить сервисы `app`, `worker`, `postgres`, `rabbitmq`, `redis`; добавить healthchecks, том PostgreSQL и единый `.env`.
- Интерфейс должен показывать статусы `queued`, `running`, `completed`, `failed`; при ошибке — безопасное сообщение и возможность повторить анализ.

**Готово, когда:** `docker compose up --build` поднимает весь стенд, а анализ продолжает выполняться worker-процессом после возврата HTTP-ответа.

## Принятые допущения

- В MVP вакансии поступают из подготовленного JSON/CSV; внешние API и парсинг сайтов остаются возможным следующим этапом.
- LLM подключается через OpenAI-совместимый API, но система остаётся работоспособной в режиме fallback.
- Один пользователь хранит одно актуальное целевое направление и уровень; история анализов сохраняется отдельно.
- Внутренний API-ключ обслуживает импорт и управление справочником, а пользовательские данные доступны только по JWT.
